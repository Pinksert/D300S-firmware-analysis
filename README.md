# Nikon D300S 官方固件解析

本项目收录尼康 D300S 的官方固件与解析。与 D300 不同，D300S 的固件是**加密**的（三层 XOR 流密码）；本仓库同时提供原始加密包、解密后的 A/B 固件镜像、解密脚本，以及完整分析报告，方便直接研究与复现。

> 姊妹项目（D300，明文固件）：<https://github.com/Pinksert/D300-firmware-analysis>

## 文件说明

| 文件 | 说明 | 大小 |
| --- | --- | --- |
| `D300S102.bin` | D300S 官方固件包（**加密**，尼康原版发布文件） | 7,864,450 B |
| `D300S_A.bin` | 解密后的 A 固件镜像（IO 协处理器；原始内部名 `a810_010200.bin`，约 512 KB） | 524,290 B |
| `D300S_B.bin` | 解密后的 B 固件镜像（主控 MCU；原始内部名 `b810_102_.bin`，约 7 MB） | 7,340,032 B |
| `decrypt.py` | 解密脚本（Simeon Pilgrim 的三层 XOR 密钥表 + 解包 + CRC 校验） | 8,487 B |
| `D300S_NT(Sc)07.pdf` | D300S 简体中文说明书（448 页，供交叉印证固件发现） | 22,900,768 B |

## 处理器平台结论

- 架构：Fujitsu **FR 系列 32 位 RISC，大端**；RTOS = Softune REALOS/FR（micro-ITRON）。
- **A 固件（IO 协处理器）**：负责测光 / 对焦 / 按键等。
- **B 固件（主控 MCU）**：负责 UI + 图像处理 + 多语言文本。
- **加密**：三层嵌套 XOR 流密码，有效周期 2^24；每个固件镜像末 2 字节为 CRC16/XMODEM，是验证解密正确性的金标准。
- D300 与 D300S 硬件平台相同，但固件内容约 73%–86% 不同（软件重写）；D300S 首次对固件包加密。

## 如何解密

```bash
python decrypt.py
```

解密脚本内置完整的 XOR 密钥表，可直接把 `D300S102.bin` 还原为解密后的包，并解出 A/B 两个固件镜像（含 CRC 校验）。

## 固件 bin 文件分析报告（D300S）

目标文件：`D300SUpdate\D300S102.bin` · 7,864,450 字节 (0x780082) · 固件版本 A/B 1.02 · 构建日期 2013-04-19

**结论摘要**

该 bin 文件**不是**原始固件镜像，而是一个**加密的固件包（bundle）**：外层用尼康三层嵌套 XOR 流密码加密，解密后是一个含 2 个固件镜像的容器。本次分析**已完整还原加密算法并成功解密**，抽出的 A / B 两份固件的 CRC16 校验**全部通过**，可作为可刷写的明文固件使用。

### 一、文件来源与外层封装

同目录的 `F-D300S-V102W.exe`（5,738,048 字节）是一个 **WinRAR 自解压包（SFX）**。在其偏移 0x16A00**  处可找到 52 61 72 21 1A 07 00** （`Rar!\x1a\x07\x00`）签名，包内唯一条目为：

```
D300SUpdate\D300S102.bin
```

因此该 bin 就是尼康官方分发的原始固件包，未经过二次加工。解压后按尼康官方流程拷入 CF 卡根目录、在机身菜单中执行升级即可。

### 二、加密特征：如何在未获密钥前判定算法

对密文做纯统计分析，得到三条互相印证的强特征，直接把算法范围锁定在"周期性流密码"：

#### 2.1 熵接近理论上限

全文件香农熵 **8.0000 bits/字节**，256 种字节值出现频次均在 0.39% 左右，无压缩文件或未加密固件的典型残留结构 → 数据已被完全扰乱。

#### 2.2 重复块只出现在 mod 256 同余的位置

以 16 字节为粒度建立全部块的索引（共 122,882 个块），统计到 **126,830 对**内容完全相同的块。关键结果是这些重复对的偏移距离分布：

```
距离 mod 256 == 0 :  126830 / 126831   （唯一例外是文件头 0x00 与 0x10 的空格块）
```

> 两个位置的明文相同 ⇒ 密文也相同，当且仅当两位置满足 a ≡ b (mod 256)。这说明密钥流以 256 字节为周期，且变换是逐字节、与分组无关的（不是 AES/ECB 这类 16 字节分组密码）。

#### 2.3 匹配长度呈连续衰减，而非整段复制

把每对重复块向两侧扩展，测得连续匹配长度分布（16 字节为单位）：

| 连续匹配块数 | 1 | 2 | 4 | 8 | 16 | >16 |
| --- | --- | --- | --- | --- | --- | --- |
| 占比 | 12.13% | 7.72% | 6.42% | 5.69% | 5.18% | 仅 457 对 |

衰减平滑而非"要么全等要么不等"，进一步排除分组密码，坐实**逐字节 XOR 流密码**；重复内容则来自固件镜像内部天然相似的相似代码/数据表段。

### 三、算法还原与解密

上述特征与已公开的尼康 DSLR 固件加密方案（Simeon Pilgrim, 2011，用于 D3S / D300S / D3100 / D5100 / D7000 等机型）一致。该方案为**三层嵌套 XOR**，逐字节生成密钥：

```
ord1 = i        & 0xFF        # 第 1 层：256 字节模式，全程循环
ord2 = (i >> 8)  & 0xFF       # 第 2 层：每 256 字节递进一字节
ord3 = (i >> 16) & 0xFF       # 第 3 层：每 64KB 递进一字节

key[i] = Xor_Ord1[ord1] ^ Xor_Ord2[ord2] ^ (Xor_Ord3_Eye[ord3] ^ fixKnownTRUE[ord3])
plain[i] = cipher[i] ^ key[i]
```

三层叠加后有效密钥流周期为 256×256×256 = **2²⁴ = 16 MB**，恰好覆盖尼康当时最大的固件包。

#### 3.1 本地交叉验证

在不依赖外部结果的情况下，用文件自身做了一次独立验证：密文前 32 字节为明文 0x20** （空格），按 i<256 时 `ord2 = ord3 = 0` 计算 `key[i] = Ord1[i] ^ 0x76 ^ 0x2F`：

```
i=0: 0x20 ^ (0xE8 ^ 0x76 ^ 0x2F) = 0x91   ✔ 预期容器魔数首字节 0x91
i=1: 0x20 ^ (0xFE ^ 0x76 ^ 0x2F) = 0x87   ✔ 预期 0x87
```

**验证通过**  密钥表与算法均正确。

```
00000020  00 00 00 02 00 00 00 70 00 00 00 00 00 00 00 00   ← 记录数=2, 首记录偏移=0x70

00000050  62 38 31 30 5f 31 30 32 5f 2e 62 69 6e 00 00 00   ← "b810_102_.bin"

```

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| `0x000000` | `0x20 (32)` | 固定魔数头：91873f9a04d225c0dc2abdbe4bb4e594ed1e372231432bcf4d8ef76be9e1fb45（各机型通用） |
| `0x000020` | `4` | 记录数 nb_record = 2（大端 u32） |
| `0x000024` | `4` | 首条记录偏移 = 0x70 |
| `0x000028` | `8` | 保留字段，全 0 |
| `0x000030` | `0x20 (32)` | 记录 0：文件名 16B + 起始 4B + 长度 4B + 保留 8B |
| `0x000050` | `0x20 (32)` | 记录 1：同上 |
| `0x000070` | `0x80002` | A 固件数据（IO 协处理器） |
| `0x080072` | `0x700000` | B 固件数据（主控 CPU） |
| `0x780072` | `0x10 (16)` | 包尾：包校验 F76F + 14 字节填充 |

各段长度之和 `0x70 + 0x80002 + 0x700000 + 0x10 = 0x780082`，与文件总长精确吻合。

### 五、提取结果与完整性校验

每个固件镜像的**最后 2 字节**存放其自身的 CRC16 校验值。校验参数：XMODEM CRC16，多项式 `0x1021`，初值 `0x0000`，覆盖范围为「长度 − 2」字节，大端存放。

| 文件名 | 大小 | MD5 | 存储校验值 | 实测 CRC16 | 结果 |
| --- | --- | --- | --- | --- | --- |
| `a810_010200.bin` | `524,290(0x80002)` | `f4f11ec77efa318e02707631a25943fd` | `0xB506` | `0xB506` | 一致 ✔ |
| `b810_102_.bin` | `7,340,032(0x700000)` | `e41f1d874959dadd5713fb2eb03e848f` | `0xB00C` | `0xB00C` | 一致 ✔ |

> 两份镜像的 CRC 均与文件内嵌值完全吻合，证明解密结果字节级无损、可直接刷写。输出目录：D300SUpdate\decrypted\

#### 5.1 A 固件头部语义

```
01 02           → 固件版本号 A 1.02
00 00           → 保留
13 04 19 13     → 构建日期字段（与 D300 1.11 相同）
"D300S Firmware A Copyright Nikon Corp."
00 04 16 ...
```

解密后熵降至 **6.77 bits/字节**，属正常未压缩嵌入式代码水平。

### 六、固件内容要点

明文固件中可直接观察到大量有价值的组件与功能字符串：

#### 6.1 B 固件（主控，Fujitsu FR 架构）

- **实时操作系统**：`Softune REALOS/FR is Realtime OS for FR Family, based on micro-ITRON COPYRIGHT(C) FUJITSU LIMITED 1994-1999` —— 确认主控为富士通 FR 系列 CPU。
- **分组密码库**：`CIPHERUNICORN-S COPYRIGHT (C) NEC CORPORATION 2006` —— NEC 的 128 位分组密码，用于机身内部数据保护。
- **图像处理**：`Copyright (c) 2000-2007 by FotoNation. All rights reserved.` / `RedEye Library v.2.10.0.0` —— FotoNation 红眼消除库。
- **视频功能（D300S 核心升级）**：`1280x720 (16:9)`、`640x424 (3:2)`、`320x216 (3:2)`、麦克风增益选项、HDMI 输出 `480p/576p/720p (Progressive)`、`1080i`。
- **双卡槽**：`[CF card slot]` / `[SD card slot]`、副卡槽职能设定、卡间复制 —— 对应 CF+SD 双存储。
- **海量多语言 UI 串**：英语、德语、法语、波兰语、芬兰语、葡萄牙语、挪威语等完整菜单文案（如 `CF-Speicherkarte`、`SD-Speicherkarte`、`Videoeinstellungen`）。
- 文件系统相关：`MSDOS5.0`、`SanDisk SDCFX-`、`HDISCVRY.DPS`。
解密后熵 **5.62 bits/字节**。

#### 6.2 A 固件（IO 协处理器）

负责测光、对焦、按键等 IO 控制（同平台机型使用 Toshiba TMP19A 类微控制器）。版本 `A 1.02`。

### 七、与 D300（非 S）1.11 固件的横向对比

工作区另有 `D300Update\` 下的 `A3000111.bin` / `B3000111.bin`——这两个文件**本身未加密**（头部即为明文），可直接比对：

| 对比项 | A 固件 | B 固件 |
| --- | --- | --- |
| 大小 | 524,290 vs 524,290 完全相同 | 7,340,032 vs 7,340,032 完全相同 |
| 差异字节 | 453,223（86.45%） | 5,360,502（73.03%） |
| 共同前缀 | 仅 1 字节（版本 1.02 vs 1.11） | 0x141 字节（前 321 字节一致，同为 FR 启动向量） |
| 解密后熵 | 6.77 / 6.73 | 5.62 / 4.67 |

> 两机型的 B 固件开头 0x141 字节完全一致（9f8050000000c011150187109f8f00008400…），说明它们共用同一套 FR 启动引导；但整体内容差异达 73%，印证 D300S 是大幅重写（加入视频、双卡槽、Fn 按钮自定义等），而非 D300 的小版本迭代。

典型的差异化字符串：

- **仅见于 D300S**（出现次数 D300S : D300）：`Movie settings` 2:0、`1280x720` 37:0、`320x216` 30:0、`Microphone` 4:0、`SD card slot` 10:0、`Assign Fn button` 2:0、`Virtual horizon` 6:0、`Eye-Fi` 68:0、`Bar code` 2:0。
- **仅见于 D300**：`Assign FUNC. button` 0:2（D300S 改名为 `Assign Fn button`）。
- **勘误**：早前结论曾把 `MB-D10`、`Camera Control Pro 2`、`i-TTL`、`AF-ON` 列为"D300 独有"，经逐条计数核对**该结论错误**——四者在两份固件中均存在（MB-D10 为 290:231，AF-ON 为 371:302，i-TTL 为 16:14，Camera Control Pro 2 为 11:24）。`Assign preview button` 亦为两边都有（2:2）。固件字符串只能证明功能存在，不能证明功能起始机型。
- 交叉验证：与 D300 两份明文固件做 64 字节块比对，**匹配数 0**，确认两者使用各自独立的封装，互不通用（与尼康官方"D300S 固件不可用于 D300"的警告一致）。
